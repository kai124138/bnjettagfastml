# XNOR-Net: ImageNet Classification Using Binary Convolutional Neural Networks

- **Authors:** Mohammad Rastegari, Vicente Ordonez, Joseph Redmon, Ali Farhadi
- **Venue / Year:** ECCV 2016
- **arXiv:** 1603.05279 — https://arxiv.org/abs/1603.05279
- **PDF:** https://arxiv.org/pdf/1603.05279
- **Code:** https://github.com/allenai/XNOR-Net
- **Topic area:** QAT & binary-NN foundations

## TL;DR
XNOR-Net makes binary CNNs work at ImageNet scale by introducing real-valued **scaling factors** alongside binary weights/activations, which sharply reduces the binarization approximation error. Binary-Weight-Networks binarize only filters (~32× memory saving); XNOR-Networks binarize filters and inputs so convolutions run as XNOR + popcount (reported ~58× faster).

## Summary
The paper proposes two efficient approximations to standard CNNs. In Binary-Weight-Networks, the filters are approximated with binary values, yielding roughly 32× memory savings. In XNOR-Networks, both the filters and the convolution-layer inputs are binary, so convolutions are computed primarily with binary (XNOR) operations and bit-counting, giving large speedups. The key idea is to accompany each binarized tensor with an optimal real-valued scaling factor (derived analytically) that minimizes the L2 error between the full-precision and binary tensors, which lets binary networks scale to ImageNet far better than naive binarization.

## Key methods / contributions
- Binary-Weight-Networks: binarize convolution filters with a per-filter scalar α (the mean absolute value of the weights) that minimizes reconstruction error.
- XNOR-Networks: binarize both weights and activations and compute convolutions with XNOR + popcount plus scaling factors.
- Closed-form optimal scaling factors for weights and inputs to reduce quantization error.
- Reordering of layer operations (BN → activation → binary-conv → pooling) for stable binary training.
- First demonstration of binary CNNs at ImageNet scale, enabling real-time inference on CPUs.

## Main results
On ImageNet, Binary-Weight-Networks substantially close the gap to full precision, while fully binary XNOR-Networks incur a larger but still useful accuracy drop; the paper reports ~32× memory savings and ~58× faster convolutions (exact top-1/top-5 numbers: see paper).

## Relevance to BNJetTag
XNOR-Net is the bridge from toy-scale binary nets to "binary at real workloads," and its **per-tensor scaling factor** trick is conceptually the precursor to the learned scales used in BitNet (and to the activation-clipping/step-size ideas in PACT and LSQ). For BNJetTag, the lesson is that pure {−1,+1} weights need an accompanying real scale to preserve accuracy — relevant to how we calibrate our binary-weight transformer and to the resource argument that XNOR/popcount maps to LUT/logic rather than DSP. It also motivates why we sweep activation precision (A8/A6/A4) instead of fully binarizing activations, since fully binary activations cost the most accuracy.
